# Senior Citizen / PWD discount: ID at sign-up, automatic at checkout

- **Where the ID is given.** Sign-up asks "Are you a Senior Citizen or PWD?" (its own step, after Delivery details), and so does Complete your profile. A yes needs the ID type, number and a front photo (back optional). A Customer who said no, or signed up before this, can send an ID from **Account settings → Senior Citizen / PWD**.
- **What happens to it.** The ID is sent for Staff review exactly as before (`senior_pwd_verifications`, Private Temporary photos, number stored only as a keyed hash, decisions through `/api/internal/senior-pwd/:id/:action`). An ID number already used by another account (pending or approved) stops sign-up at the Senior/PWD step, before any login is made: `checkSeniorPwdIdNumber` (`lib/senior-pwd/check-id-action.ts`, rate-limited per address) answers the step's Continue, and `submitSignUp` checks again before creating the login. Either way the Customer sees the toast "This ID is already used by another account." and the message beside the number. Complete your profile and Account settings refuse it the same way, before anything is saved or uploaded. If file-storage is down, or another account wins a race for the same number, the sign-up still goes through and the Customer is told they can resend from Account settings.
- **The number is read off the photo.** When the Customer chooses the front (or back) photo, Tesseract reads it in the browser (`lib/senior-pwd/id-photo-reading.ts`; the image is never uploaded to read it) and fills the ID number field if it is still empty, for the Customer to check and correct. The reading also goes to the server as `idNumberRead`, where it is hashed and compared with the number sent; only the outcome is kept (`senior_pwd_verifications.id_number_read`: `matched`, `differs` or `unread`, migration `0069`), and CREOMS flags `differs` for review.
- **Checkout asks nothing.** Orders from a Customer with an approved, unexpired ID get the discount automatically on one unit of their priciest item. While an ID is pending, declined, revoked or expired, Orders are placed at full price and are never held for the ID check.
- **The rule comes from CREOMS.** `lib/senior-pwd/discount-rule.ts` reads `crms.senior_pwd_discount_settings` (Commerce Settings: percentage or pesos, and a limit in pesos per day, week or month) on every Order placement and on the Checkout page. If the row cannot be read the default applies (5% off, up to ₱125 per week). **The storefront's database role needs SELECT on that table**, as it has for `crms.delivery_settings`; without it the default is used silently.
- **Orders keep their rule.** Each Order saves its discount and the limit and period it was placed under (`orders.senior_pwd_limit_in_centavos`, `senior_pwd_limit_per`, migration `0063`). The cap at confirmation counts the ID's other confirmed Orders in the same Philippine-Time day, week or month and reduces the discount to what is left. Orders from before this change have no snapshot and use ₱125 per week.
- **Same ID number on another account.** The ID number is only ever stored as the keyed hash (`id_hash`). When a Manager approves the ID, the account's full name is copied beside the hash (`verified_name`, migration `0069`), so the record holds the name it was verified under even if the account is renamed; the photos are then deleted. Sending a number that is pending or approved on another account is refused with "This ID is already used by another account." (checked under a per-number lock, so two simultaneous submissions cannot both pass). A number last seen declined, revoked or expired on another account is accepted but flagged: `senior_pwd_verifications.same_id_as_verification_id` points at that other account's latest verification (migration `0064`). CREOMS has no grant on `id_hash`, so this pointer is how it shows "this ID number is already used by another account" and names whose. CREOMS needs `GRANT SELECT (same_id_as_verification_id, id_number_read, verified_name)` (`docs/db/creoms-senior-pwd-readonly.sql` in the CREOMS repo). Approval still refuses a number already verified on another account.
